## 一、RFM 分层：三版迭代

### v1 · 均值阈值法

```python
high = row['R'] >= rfm['R'].mean()   # 三个维度各自 ≥ 均值
```

**结果**：重要价值客户占 **30%**。

**问题**：五分位打分后均值约 3.0，判据实际是"三样都 ≥ 3 分"，即各维度排在后 60% 就算高。
单看联合概率应是 0.6³ ≈ 21.6%，但 **R、F、M 三者高度正相关**（买得频繁的人通常也买得贵、也近期活跃），
联合概率被大幅抬高，最终落到 30%。

**为何要改**：30% 的人被划进最高价值层，运营上无法聚焦；熟悉 RFM 的面试官扫一眼比例也会觉得阈值偏松
（常见合理区间 15%~25%）。

---

### v2 · 加权综合分

```python
rfm['Score'] = 0.2 * rfm['R'] + 0.3 * rfm['F'] + 0.5 * rfm['M']
q80 = rfm['Score'].quantile(0.8)
```

**结果**：重要价值客户 20.4%（符合二八），但**重要保持客户只剩 0.6%（25 人）**。

**问题**：把 R、F、M 混进一个分数，R 的权重只有 0.2，信号被 F 和 M 稀释；
更关键的是 R 与 F/M 正相关 —— 流失很久的人频次和金额通常也低，综合分自然上不去。
所以"综合分很高、但 R 很低"的人几乎不存在，这是**方法的结构性必然**，不是数据问题。

---

### v3（定稿）· 价值与状态分离 ⭐

```python
rfm['Value'] = 0.4 * rfm['F'] + 0.6 * rfm['M']      # 价值：只看消费行为
q80 = rfm['Value'].quantile(0.8)
live = row['R'] >= 2                                 # 状态：由 R 独立判定
```

**核心洞察**：R（近度）是**状态标签**，不是价值组成部分。
"这个客户值多少钱"由 F（频次）和 M（金额）定义，跟他最近来没来过无关；
"他现在活跃还是流失"由 R 判断。两个维度分开算，不要揉进一个分数。

另一处调整：活跃判据从 `R >= 3` 放宽到 `R >= 2`。
这份数据里高价值客户人均 R 仅 17 天，`>= 3`（约"90 天内有回购"）对高频零售太严，
会把大量"只是两个月没来"的正常客户误判成流失。

**结果**：重要价值客户 22.8% / 69.5% GMV，潜力客户 26.8% / 18.7%，结构健康。

---

### 面试话术

> 百分之多少算"高价值"没有统一标准。我先用五分位做无先验假设的划分，发现均值阈值下高价值层占到 30%，
> 区分度不够；改用加权综合分后，"高价值且已流失"的人群几乎消失 —— 因为 R 和 F/M 正相关，
> 综合分会自动掩盖流失信号。最后我把价值（F/M）和状态（R）拆成两个独立维度分别判断，
> 结果才正常。这让我意识到 RFM 里 R 的角色是状态标签，而不是价值的组成部分。

## 二、重要保持客户只有 11 人：不是 bug，是业务真实

修正方法后，"高价值但已流失"的客户仍只有 11 人。这次**不要再调阈值**。

算一下就清楚：高价值层 986 人，流失的只有 11 人，**流失率 1.1%**。
这份数据来自英国**批发型**零售，客户多为持续下单的经销商，靠长期供应关系维系，
本来就不太会"悄悄消失"。

**正确的应对是换叙事**：运营重点从"唤醒流失客户"改为"**推动潜力客户升级**" ——
潜力客户 1,150 人、贡献 18.7%、人均 R 只有 49.8 天（仍然活跃，只是买得不够多），
把他们推上高价值层的空间远大于唤醒沉睡客户。

> 这个结论比"8 类人群各配一句策略"有洞察得多，因为它是**从数据里长出来的**，不是套模板。

## 三、KMeans 交叉验证：怎么读结果

### 判据一：轮廓系数 k=2 最优，为什么还用 k=6？

轮廓系数衡量**几何分离度**，不管业务意义。k=2 最优（0.435）说明数据天然分成两大团 ——
"高价值一小撮 + 长尾一大片"，这本来就是零售数据的典型形态。

选择 k=6 的理由：需要与 RFM 的 6 类分层对齐做比较，且轮廓系数仅从 0.435 降到 0.316，
聚类质量仍然可接受。这是**业务可解释性优先于几何指标**的权衡，README 里要写明白。

### 判据二：ARI = 0.408

调整兰德指数：0 = 随机，1 = 完全一致。**0.3~0.6 表示结构大体吻合但边界不同**，属正常预期。
低于 0.2 才要回头检查分层逻辑。

补充一个更直观的判据：**簇人均 GMV 与簇内高价值客户浓度的 Spearman ρ = 0.986** ——
簇越"贵"，里面聚集的高价值客户比例越高，单调关系几乎完美。

### 判据三：重要价值客户"散在 3 个簇"是印证成功，不是失败

簇名按人均 GMV 降序排列，簇 1/2/3 正是 GMV 排名前三的高价值簇。
重要价值客户在这三簇的占比为 33.3% + 54.1% + 10.6% ≈ **97.9%**。
（若你之前跑出过 98.4%，属随机性/中间状态导致的微小差异，以重新全量复跑为准。）

**这说明 KMeans 完全独立地把这批人识别成了高价值**，只是按行为模式把高价值层进一步切细了
（近期高频高额 / 高额但久未回购），而 RFM 把它们归成了一类。
**量级判断一致、边界粒度不同 —— 这正是交叉验证想看到的结果。**

反过来说，如果重要价值客户均匀撒在 6 个簇里、高价值簇里混着大量低价值人群，那才叫分层失败。

### 必须主动说明的局限

两套方法用**同一组特征**（R/F/M），不是完全独立的验证，严格来说只是
"同一特征上的两种划分逻辑互相印证"。真正的独立验证需要新数据源或业务反馈。
面试时主动点破这一点，比被追问时支吾强 —— 面试官考的是你对方法边界的认知。

## 四、Cohort 留存：两个截断陷阱

### 左截断（首个同期群虚高）

数据从 2010-12-01 开始，所有在此之前的**存量客户**都被算成"2010-12 首次购买" ——
他们根本不是新客，留存天然高（次月 36.5%，远高于平均的 20.3%）。

**处理**：报告里剔除首个同期群再平均（得 18.9%），或至少加一句说明。
主动指出这一点是明显加分项。

### 右截断（右下角三角 NaN）

2011 年 11 月之后进来的客户根本没有"次月"可观察。矩阵右下角的空白是**必然的**，不是 bug。

### 留存曲线为什么回升？

第 3、9~11 个月留存明显回升（如 2010-12 群从 32.1% 回升到 40.2%），
这是零售数据的**季节性** —— 圣诞采购季客户会周期性回流。
App 类数据的留存是单调下滑的，零售数据有波峰。

> 面试被问"留存为什么回升"，答"节假日效应"，顺手可以引出"做同比而非环比更公平"。

## 五、代码层面的坑（都是真踩过的）

| 坑 | 现象 | 解法 |
| --- | --- | --- |
| `qcut` 报 "Bin edges must be unique" | Frequency 大量重复值（很多人只下过 1 单） | 先 `rank(method='first')` 再 `qcut` |
| Recency 出现 0 值 | 基准日取了当天 | 基准日 = `最大日期 + timedelta(days=1)` |
| CustomerID 变成 17850.0 | 读入时被推断为浮点 | `dtype={'CustomerID': str}` |
| 中文标题全是方框 | 缺中文字体 | `plt.rcParams['font.sans-serif'] = ['SimHei', 'Microsoft YaHei']` |
| Apriori 内存爆炸 | 商品×订单布尔矩阵过大 | 只挑中小国家（如 France）再跑 |
| Power BI 折线是一条水平直线 | 日期表与事实表关系未建立 / 时间列带时分秒 | 建 `订单日期 = INT([InvoiceDate])` 再建关系 |
